# Contributing / Contribuciones

We welcome documented examples, fixes, security improvements, translations and tests.

1. Open an issue describing the problem and expected result.
2. Create a branch, use fictional test data, and never commit credentials or private customer data.
3. Keep every workflow small, importable, and documented. Verify compatibility in a running n8n environment when possible.
4. Run `python -m unittest discover -s tests -v` and include a clear test report in your pull request.
5. Submit a pull request with rationale and limitations. Contributors retain credit for their work under the MIT license.

No spam, misleading AI claims, copied proprietary automation templates, or unsafe unsolicited-message systems.
